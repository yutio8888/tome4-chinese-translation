# 全库生硬描述快速扫描方案（精简版）

日期：2026-10-03。状态：用户已同意（含第 6 节的两项用户决定）；A、B、C 档均已完成（A 档 636 处、B 档 323 处、C 档 485 处，交叉复核再修正 6、4、8 处），见[报告](../evidence/quality/awkward-scan3-20261003/REPORT.md)。C 档因通读召回过低改为逐条裁决，做法见报告。本稿取代同日的详细版；详细版未提交，仅在本机备份于 `.artifacts/plan-backup/`。

## 1. 目标与口径

找出并修正读者明显会卡住的中文：病句、重复表述、翻译腔，以及打断阅读的括注或追加解释。

这是一次润色，不是覆盖证明。漏掉少量问题可以接受，以后发现再改。交付时只说明读过哪些、改了哪些，不宣称“全库已无生硬描述”。

以下内容不在本轮处理：

- 机制对错：英文与代码不一致时，按 [10-03 撤回决定](../evidence/quality/mechanics-rollback-20261003/WITHDRAWAL-DECISION.md)另记疑点，不写进译文。
- 术语和专名改名，以及跨库措辞统一。
- 只是“还能更好”的偏好润色；同一条不做多轮打磨。

## 2. 范围

基线 `1663a0a7`。按 manifest 用 LuaJIT 载入 11 个译文文件，共 30,308 条，英中合计 3,658,983 字符（实测）。中文不少于 15 字的条目只有 10,867 条，却占全部字符的 89%。其余 19,441 条多为名称、标签和短提示。

- **短条目**（中文少于 15 字）：只做规则检索。
- **长条目**：按下表分三档通读，每读完一档都可以停下。
- **开发／示例文件**（`mod-example*.lua`、`tome-addon-dev.lua`，共 153 条）：不读。

|---|---|---:|---:|---:|
| A | 技能、状态效果、物品、出生／职业说明 | 5,812 | 1,186,665 | 30 |

每块不超过 4 万字符，条目不拆开（最长单条约 2.8 万字符）。C 档单条较长，装箱后比按字符估算的 36 块多 3 块。

## 4. 步骤

### 4.1 导出

用一个脚本经 LuaJIT 载入全部文件，写出 `.artifacts/i18n/awkward-scan3/entries.jsonl`。每条记录包含文件、行号、section、source_tag、英文、中文和档位，同时记录 HEAD。候选 ID 用导出时的“文件:行号”；修复前按英文和 section 回查当前位置，不依赖行号。

### 4.2 规则检索（全部 30,308 条）

以前两轮的实际问题为起点，初始规则如下：

- 同一条内出现重复，如“中的其中”“提供……所提供的”、以“你使用你的”开头，或同一个 2—4 字词在一句中出现两次。
- 一个分句里有三个以上“的”。
- “的／地”误用，如“惊讶的发现”，用常见副词小词表匹配。
- 中文括注多于英文括号，或括注里出现“实际”“即”“注”“否则”“而非”等解释词。
- 中文出现“注：”“实际上”“否则”等说明语，而英文没有对应词。
- 翻译腔标记：“以至于”“并不是那么”“对……进行”“被……所”。

每条规则的前 30 个命中先交裁决员。裁决员判“不改”超过一半的规则，收紧后重试或直接放弃；其余规则的命中全部交裁决员。校准结果：近距重复词（11／30 判改）、括注（7／30）、说明语无英文对应（8／30）三条放弃；固定重复式、的字链（21／30）、的／地误用（6／10）、翻译腔标记（15／30）保留。保留规则的命中随所在块一起交裁决员。上一轮同一基线的检索结果可作参照：关键词命中 30 条、结构命中 49 条、宽松措辞命中 315 条（见 [SCAN.json](../evidence/quality/awkward-descriptions-scan2-20261003/SCAN.json)）。

### 4.3 试跑：三轮对比

试跑在 A 档进行，共三轮，每轮取一个不同的 A 档块：

1. GPT-6.1 Sol 和 DeepSeek V4.1 Flash 并行读同一块，使用同一份通读提示。
2. 主代理合并两边的报告和该块的规则命中，交给裁决员。线索只标“线索 1、线索 2”，不标模型名。
3. 记录每个模型的报告数、判改数、判不改数（误报）、判搁置数、独有确认数（只有它报出且判改）、单块耗时和输出是否合格。

三轮之间可以修正提示里明显的理解偏差，但须记录版本。三轮结束后，主代理向用户提交对比简报和建议，由用户决定后续通读用哪个模型，或者 A 档是否两个模型都读。试跑的三块计入 A 档进度，不再重读。

试跑结果（A-017、A-003、A-027，共 489 条；三轮未改提示）：

| | GPT-6.1 Sol | DeepSeek V4.1 Flash |
|---|---|---|
| 报出条目 | 55 | 85 |
| 判改／判不改 | 53／2 | 76／9 |
| 占三块全部判改项（87 条） | 61% | 87% |
| 只有它报出的判改项 | 10 | 33 |
| 单块耗时 | 77—104 秒 | 75—374 秒 |

两者合计找到 86 条；百分比以本次被找出并判改的条目为分母，不是绝对召回率。长条目约 18% 被判为应改，按此粗算 A 档约 1,000 条、三档约 1,900 条（估算）。用户据此决定：DeepSeek 单独通读；先只做 A 档，做完再决定 B、C 档。

### 4.4 通读（长条目，按 A → B → C）

- 每档内按文件顺序切块，让技能名和说明相邻。每块约 4 万字符，写成独立块文件。
- 每块按试跑后选定的方式派发，使用文末的固定通读提示，只返回有问题的条目。输出格式不对就重派该块一次。
- B、C 档开始前，从各自第一块中抽 30 条没被报出的条目交裁决员复查。漏报达到 3 条时，缩小块或换模型。

### 4.5 裁决

候选来源包括规则命中、通读报告，以及第二轮的 14 组、17 处（[REPORT](../evidence/quality/awkward-descriptions-scan2-20261003/REPORT.md)）。第二轮的结论由当时的主代理作出，因此不直接沿用，而是把它的理由和建议作为线索交裁决员重新判定。同一条目的多条线索合并为一个候选。刚调整过的 16 条照常参与通读，但不为此重开。

每次裁决最多 40 条候选或约 6 万字符，使用文末的固定裁决提示。裁决员给出的结论如下：

| 结论 | 含义 |
|---|---|
| 改 | 明确的病句、重复或翻译腔，或中文多出英文没有的解释（删回英文范围）；附替换片段 |
| 不改 | 原句可读，或原文本来如此；写一句理由 |
| 搁置 | 需要查机制、拼接上下文或术语才能判断；列入报告，本轮不处理 |

线索的严重度不影响结论。输出格式不对就重派该次裁决一次。

### 4.6 修复

每攒够约 100 条“改”，组成一个修复包（试跑后由原定的 20—30 条放大，因为套用和检查都是自动的）。主代理逐字套用裁决员给出的替换片段，不自行修改措辞。本轮只套用 A 档条目；校准中判改的 B、C 档和短条目先记录，等 B、C 档的决定。

出现以下情况时，主代理把该条连同原因退回裁决员重判，不自行改判：

- 替换片段在原文里找不到，或出现不止一次。
- 改后占位符、颜色标记或换行与原译不同。
- 改后检查失败。
- 新译删掉了英文里的限定（may、chance、each 等）。

同一英文在其他位置复用时：若对方中文与被改条目原文完全相同，按同一裁决逐字套用相同替换；若中文不同，交裁决员另行判定。

每包提交前运行以下检查：

```bash
python3 -B tools/i18n lint --strict
python3 -B tools/scan_runtime_collisions.py
python3 -B tools/classify_runtime_keys.py
python3 -B tools/i18n build --profile addon --component tome --require-complete
python3 -B tools/i18n build --profile full
python3 -B tools/i18n publish   # 默认 dry-run，不写发布仓库
git diff --check
```

三个 DLC 译文文件在工具链中没有 addon 或 full 构建目标（addon 构建报 `no addon component has a pinned official baseline`），由严格 lint 和下述 LuaJIT 前后对比核验；上面的构建与 publish dry-run 覆盖 engine、boot 和核心 tome。

另外用 LuaJIT 前后对比，确认只有点名条目的 target 改变，source、source_tag、args_order 和 special 均不变。同时生成“英文／原译／新译”三栏对照表，与改动一起提交。每包一个 commit；是否推送按当时的授权。

A 档完成后，应用户要求增加一轮交叉复核：全部修改交 GPT-6.1 Sol 复核，异议交独立 Opus 5.5 裁决为维持、修正或回退，主代理机械套用。复核只做一轮，不进入反复打磨。主代理需核对每个复核员是否完整读到全部条目，未确认的行另组补充包重读。

A 档执行中发现三点，B、C 档开始前应先落实：

- 裁决输入要附带 `args_order`，提示中写明占位符的先后顺序不得改变（`mod-tome.lua:21042` 曾因对调参数被拦下）。
- 提示中写明技能描述里数字占位符与中文之间保留一个半角空格（lint `talent-placeholder-spacing`）；A 档有 41 条为此做了机械补正。
- 套用脚本增加占位符换位检测：比较数字占位符紧邻单位词的先后顺序。同为 `%d` 的两个参数对调文字位置时，按顺序比较占位符拦不住（`tome-cults.lua:3096` 由交叉复核发现）。

修改过的条目会在 WP2-Lite 队列中成为待复审的新 revision。是否再走那条管线复审由用户决定，本方案不作要求。

## 6. 与仓库规则的关系

本方案不修改 [AGENTS.md](../AGENTS.md)、角色或契约。以下两项偏离现行规则，已由用户于 2026-10-03 明确同意，只适用于本次扫描：

1. 通读和裁决 agent 经 Paseo 创建和归档，但**不走** [surface v1 契约](paseo-translation-surface-screen-v1-contract.md) 或其他审核契约的 envelope、lane、身份回显和 harvest 流程。
2. 候选的改与不改由独立的 Opus 5.5 裁决员判定，而不是 AGENTS.md 默认的主代理裁决。主代理只做机械套用和检查，发现客观问题时退回重判。

以下情况停下询问用户：试跑结束后的通读模型选择、门禁失败且无法归因、需要术语或改名决定。其余情况记为“搁置”，继续往下做。

## 附 1：通读提示（固定）

```text
你是只读的中文译文通读员。请只读取指定的块文件，不要读写其他文件。
文件每行一条 JSON：id、section、英文 source、中文 target，来自游戏《马基埃亚尔的传说》(ToME4)。

只找读者会卡住或明显别扭的中文：
1. 病句：主语、指代、否定或因果关系读不通。
2. 重复：同一意思说两遍，如“中的其中”“提供……所提供的”。
3. 翻译腔：生硬直译、过长的“的”字修饰链、不自然的搭配。
4. 打断阅读的括注或解释，以及中文多出英文没有的内容。

不要报：只是“还能更好”的措辞；术语和专名的选择；游戏机制是否正确；
占位符（%d、%s、#COLOR# 等）本身；角色口吻、方言、刻意重复。

只输出一个 JSON 数组，每个元素为
{"id": "...", "type": "病句|重复|翻译腔|括注或多出内容", "excerpt": "问题片段", "reason": "一句话理由", "suggestion": "替换片段"}。
没有问题就输出 []。
```

## 附 2：裁决提示（固定）

```text
你是独立的中文译文裁决员。请只读取指定的候选文件，不要读写其他文件，也不要查阅游戏源码。
文件每行一条 JSON：id、section、英文 source、中文 target，以及 clues（来自规则检索或通读员的怀疑，
含问题片段、理由和建议）。线索可能是误报，请对照完整英文和中文独立判断。

每条候选给出一个结论：
- 改：中文确有病句、重复、翻译腔，或打断阅读的括注、英文没有的额外解释。
- 不改：读者能顺畅理解，或原文本来如此（角色口吻、刻意重复等）；只是“还能更好”也判不改。
- 搁置：要查游戏机制、拼接上下文或术语才能判断。

判“改”时给出替换：old 必须是现中文里只出现一次的连续片段，new 是替换后的片段。要求：
- 整句重读，同一句里其他明显问题一并处理，与问题无关的部分不动；
- 意思与英文一致，不删除 may、chance、each、最多、至多等限定，不新增英文没有的内容；
- 占位符（%d、%s、%%、%0.2f 等）、#COLOR# 等标记、换行和现有术语原样保留。

只输出一个 JSON 数组，每条候选一个元素：
{"id": "...", "decision": "改|不改|搁置", "reason": "一句话理由", "edits": [{"old": "...", "new": "..."}]}
“不改”和“搁置”的 edits 为 []。
```
