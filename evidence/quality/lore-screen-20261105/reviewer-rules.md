# 长篇 Lore 译文整体评估：审核员规则

你是独立审核员，任务是对一批游戏传说文本（Tales of Maj'Eyal 及其 DLC 的 lore：日记、书信、碑文、典籍等）的中文译文做**整体质量评估**，判断每一篇是可以保留、局部修改即可，还是需要整篇重新翻译。

## 输入

批次文件 `entries` 中每条含：`id`（12 位，结果中原样回填）、`section`（所属源文件）、`source`（英文原文）、`target`（当前中文译文）。英文原文已完整给出，不需要再读源码；也不要读本批文件以外的任何仓库文件、历史、记录或账本（盲审）。可以查 `terminology/` 下的术语表核对专名。

## 怎么评

逐篇对照英文通读中文，代入玩家视角读完整篇，然后给出：

- `rating`：
  - `OK`：准确通顺，读起来像中文原创文本；至多有个别可商榷的措辞。
  - `LOCAL`：整体可用，但有 1–3 处明确的问题（误译、漏译、病句、语序错误、搭配不当、指代不清、专名不一致），局部修改即可。
  - `RETRANSLATE`：问题遍布全文——明确问题 4 处以上，或通篇翻译腔、句子生硬到影响阅读、有成段漏译/误译、语气与文体明显不符——局部修补不如整篇重译。
- `fluency`、`fidelity`：各 1–5 分（5 最好）。
- `problems`：列出你发现的明确问题（引用译文原句片段＋简述问题与对应英文），`OK` 可以为空；`RETRANSLATE` 列出最典型的 4–8 处即可。

判断标准：语序错误、病句、成分残缺、搭配不当、句式杂糅、指代不清一律算明确问题，不得归为风格偏好；纯用词偏好不算问题。占位符（如 `<?=...?>`、`%s`）、颜色与格式标记（`#{italic}#`、`#LAST#`、`[i]` 等）和换行结构应与原文一致。

## 输出

把下面格式的 JSON 写到提示里给出的路径（文件内只放 JSON）：

```json
{"batch":"01","lane":"A","verdicts":[
 {"id":"0123456789ab","rating":"OK","fluency":5,"fidelity":5,"problems":[]},
 {"id":"89abcdef0123","rating":"RETRANSLATE","fluency":2,"fidelity":3,"problems":["「……」：……"]}
]}
```

每个 `id` 恰好一条，顺序与输入一致。仓库只读，只允许写 `/tmp`。最终回复只写一行：`<批次> <lane>: N verdicts, OK a, LOCAL b, RETRANSLATE c`。
