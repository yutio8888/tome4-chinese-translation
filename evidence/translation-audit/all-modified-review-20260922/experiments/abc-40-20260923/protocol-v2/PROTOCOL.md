# 修订协议 v2

来源：用户要求核实prompt/流程后发现v1依据优先级、分类合并和源码搜索边界不够明确，并且Opus重试prompt与其他臂不相同。v1仅保留为协议预试验，不用于本轮正式配对统计。

三臂fresh会话统一使用本目录INPUT.md，样本仍是原40条，字节不变。由同一条启动prompt进入同一冻结输入；Opus5.5/GPT-6 Sol/AGY Gemini3.8 Flash均High。不得透露v1任何结论。提供方差异和High不等算力限制继续有效。

正式统计使用v2各臂首份完整、读取合规的输出。运行错误或边界无效各臂最多一次fresh retry；不会因答案错误重跑。任一臂仍不完整或越界，明确缺失而不混入v1补齐。模型响应快慢不决定取舍。

非参赛REVIEWER先盲审全部40条得到参考，冻结后将v2各臂及盲审观察去除模型身份、按entry/claim稳定排序交fresh REVIEWER逐项核验；同条多个观察不得以票数判真；三方一致OK也复核。参考仍是模型基于源码的暂定参考。客观证据不足/实质分歧未解的项pending，不强制gold二分。不得以一个GPT模型裁决自动宣称GPT参赛者客观更好。

沿用根SPEC的指标，补明：主正确率以三臂都有明确判定且参考可确定的共同条目为分母；同时每臂以全部参考可确定条目为分母报告correct/N（弃权和缺失算未正确）。Gold阳性上只报错误问题不算命中，即使二值标签同为ISSUE。逐claim precision/recall另算。无分母记N/A。流程合规与模型判断分开。40条便利样本单次探索性结果，不作显著胜负或全库结论。

全生命周期和只读守卫沿用根PLAN。记录逐dispatch prompt/input SHA256及冻结清单，派发前写入；不覆盖v1，不提交、不push、不改旧campaign。
