# 校准后40条有界验证

完成时间：2026-09-23。本轮已停止，两名审核子代理均已确认归档。原 ABC 第15–20组没有恢复派发；原14组报告、10条校准记录、术语库及生产译文均未改写。

本轮从剩余412条未派发、未覆盖的条目中，按组件和英文长度固定种子抽取40条：Orcs 36条、Possessors 4条，短15、中17、长8。它是有意增加长文本比例的研究样本，不能代表全仓，也不能与旧样本直接比较来宣称准确率提升。抽样规则、完整输入与哈希均已冻结。

## 结果

主代理先完成并冻结全40条初审，再读取 Opus5.5 与 GPT6 Sol 的独立输出，逐项核验。最终是 **11条 ISSUE、4条 PENDING、25条 OK，22项确认偏差、4项未决问题**。其中3项未决来自忠实沿袭英文的机制描述疑点，另1项为罕见词义证据不足。这里的“确认”是可复查的宿主裁决，不是人工金标准，也不构成生产 DONE_VERIFIED。

完整逐条结论、短引、反证及调用证据见 [FINDINGS.md](FINDINGS.md)；两路37项编号观察及17项未编号建议的归并见 [CLAIM-CROSSWALK.json](CLAIM-CROSSWALK.json)。原始报告见 [Opus](reports/opus.md)、[Sol](reports/sol.md)。没有以多数票覆盖证据。

两路以 confirmed 提出的主张合计覆盖16/22项（72.7%）；这是对本次宿主裁决集的覆盖，**不是已测得真实召回率**。若把被写成 advisory 的正确观察也算作“发现”，覆盖会不同，机器结果另保留该口径，不能混用。样本只有一次，不能据此作稳定的模型胜负或成本效率结论。Sol 未提供价格字段，不能记为零；两家 token 字段口径不同，原值保存在 RESULT.json，未擅自折算总用量。

## 校准是否起效

- 两路均未把 core 术语直接强套到 DLC，也未把 `all sources` 的概括译法“受到额外伤害”判为确认缺陷。
- 两路均未机械地按空行、空格、大小写强调计缺陷。20条实际格式化文本的参数类型、数量及 args_order 静态检查通过；其余文本的姓名、颜色与样式标记人工核对，未发现消费错误。未做游戏运行测试。
- “风味文字影响小”与“没有错误”仍混淆。Opus 将 `over 40%`、`up to four years` 等明确数量关系变化降为建议，而 Sol 与宿主确认其语义变化。下一版规则应把**正确性**与**修复优先级**分为两个字段，避免轻微真实偏差被吞掉，同时也避免逐字漏译检查。
- Sol 对 `detonator→炸弹` 的指控被撤销：同一物品源码的 subtype 为 bomb，desc 明说 `This bomb`。需要继续要求“找到最强反证”，尤其是在同一实体的定义与当前日志之间查证。
- Opus 对罕见词 `pinaciphobia` 直接确认，却未提供词义来源。该项暂不计确认命中或误报。宿主另做了词义补查，相关网络列表不足以代替可适用的定标证据；详情见 [LEXICAL-SUPPLEMENT.md](LEXICAL-SUPPLEMENT.md)。

本轮27条双臂共同 OK 全部复查，发现 entry-03855 的两处语义偏差：`the only type of person` 变成“世界上唯一一个”，`rich potion-brewer` 变成“普通药水贩子”。另外3条共同 OK 存在上游机制适用性缺口。长文不能只做“主旨大致成立”的检查；后续至少应检查人物/集合、时间、条件、数值及因果这些信息。

宿主也有初审修订：entry-03830 的草药类别可由同实体的 type 和 desc 明确补足；entry-03855 粗口的拒斥意图可由后句作弊说明补足。两项从确认降为建议，初稿仍原样保留在 HOST-INITIAL.json；未用另一真实缺陷为错误理由兜底。

## 术语范围提案

`scope=core` 目前的定义确实排除五个 DLC 组件。这是现行规则边界，**不意味着共享游戏机制应该永久使用不同译名**。本次筛查78条 core 机制记录后，给出了3条逐行范围调整提案：小写 `global speed` 的 `_t`、`tformat` 两行，以及 `Physical Power / tformat`，从 core 改为 global；译名、状态和标签不改。

证据、未扩展其他行的理由和补丁分别见 [SCOPE-AUDIT.md](SCOPE-AUDIT.md)、[SCOPE-AUDIT.json](SCOPE-AUDIT.json)、[TERM-SCOPE-PROPOSAL.patch](TERM-SCOPE-PROPOSAL.patch)。本轮只交付提案，未将新规范偷渡进已冻结的模型测试。若下一步应用，应另冻结术语来源并仅重审实际受影响条目，不追溯改写实验评分。

## 下一步建议与停止边界

1. 将这3条 scope 提案作为下一次有界规则维护的具体改动；不批量改所有 core。
2. 在现有校准规则上补两点：正确性与影响级别分离；每项确认主张必须检查最强同实体/同段反证。罕见词义无可核对来源时保留待确认。
3. 保留长文本的共同负例复查。本次没有证据支持直接取消其中一路，也没有证据支持恢复连续批次。

用户指定的三类边界表达已经写入本轮 INPUT：列“需要澄清”，不计确认错译。新40条没有直接包含原三条争议实例，因此本轮只能验证规则执行的一部分，不能声称三类歧义都已得到实测解决。

本轮在40条交付处结束。验证脚本检查冻结输入、宿主初审、2797份既有证据文件及23份生产/术语文件未变，并检查两路40行覆盖及归档；不运行与只读研究无关的生产构建，不宣称生产完成。
