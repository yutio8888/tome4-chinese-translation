# 下一步译文复核优化建议

本次由三个 Codex 内置子代理分别分析模型组合、裁决质量和下一轮实验设计，主代理核对关键计数后汇总。仅分析已完成的14组报告，没有启动新审核、修订旧评分或修改生产规则。以下是待验证的优化方案，不是已验证的生产配置。

核心建议：先校准判定口径，再验证 Opus＋Sol 的独立双臂复核；不要仅凭条目正确率选择单一模型，也不要用多数票替代证据裁决。

## 支持建议的证据

主比较覆盖520条，其中481条已裁定，包含418项暂定确认缺陷。

| 观察 | 结果 | 含义 |
|---|---|---|
| Opus／Sol条目正确数 | 435／439；配对独对23／27 | 差4条，不足以据此认定稳定优势 |
| Opus＋Sol明确检出的缺陷并集 | 314/418，75.1% | 比单独Opus增加69项，比单独Sol增加101项 |
| 加入Gemini后的并集 | 331/418，79.2% | 增加17项；其中9项另两臂无匹配观察，8项Opus曾标为建议 |
| 三臂都未明确检出的87项 | 59项无匹配观察、27项仅建议、1项仅待确认 | 发现不足与判定尺度问题必须分开分析 |
| 三臂均判OK/ADVISORY、参考判ISSUE | 11条 | 一致阴性不能直接当作可靠通过 |

“无匹配观察”仅指SCORING中没有被裁决映射到该缺陷的观察，不推断模型的内部认知。上述计数由主代理按第2–14组SCORING独立重算。参考仍是模型裁决，不是人工真值。

## 优先调整

### 1. 先做判定校准，保留旧结果

已知的明确尺度差异是：第12组将“all damage→伤害”列为建议，第14组却将同类省略列为缺陷。源码证明效果覆盖全部伤害，不能单独证明中文泛称一定丢失了范围；需要解释完整语境为何足以或不足以承载原意。

先校准下列10条，不将其当作新的准确率测试集：

| 条目 | 校准目的 |
|---|---|
| 03620、03714 | 显式量词与中文泛称的边界 |
| 03627、03729 | 文本缺陷、机制旁证和未决断言拆分 |
| 03605 | 动态拼接的不同分支 |
| 03689、03692 | 错引译文、忽略完整段落 |
| 03595、03596 | 三臂共同阴性中的潜在漏项 |
| 03646 | 源码支持可能纠正上游时，能否保持待确认 |

先隐藏模型身份、旧判定及分数，独立写出支持证据与反证，再揭示旧裁决。仍有语言边界争议的条目交人工校准；无法人工核验时继续保留暂定性质。不要将27项建议全部自动升级为缺陷，也不要覆盖原始报告；新增校准结果和敏感性重计另存。

### 2. 把“发现”“裁决”“影响”分开记录

最小claim是一个可独立裁决的语义变化，记录原译短引、完整语境、具体变化、归因、证据及缺失证据。

- 文本缺陷与支持它的机制解释分开。解释被推翻不一定撤销文本缺陷；命中同条另一项错误也不能挽救错误理由。
- 单列“观察覆盖率”和“原本明确报错的缺陷召回率”，区分没提出问题与判定尺度不同。
- 正确性与用户影响分别标注。轻微但明确的遗漏仍可算缺陷；影响玩法、操作或关键事实的问题优先核验，措辞偏好不升级为事实缺陷。
- 39条只是条目级PENDING；ISSUE条目中的P claim也要建立未决索引，并记录解决它所缺的版本、调用点、名称映射或规则。

### 3. 将Opus＋Sol独立双臂作为首选验证方案

两臂先各自审核相同材料，再匿名合并，防止后一臂只顺着前一臂的意见检查。裁决者既核对正面观察，也抽查双方都判无问题的条目。

Gemini可保留为抽样补审臂，先测新增正确观察、误报和核验负担，而非默认全量加入或直接淘汰。本次17项增益中有8项主要体现判定差异，不能都解释为独特发现能力；现有样例也不足以证明其专擅语法或叙事。没有成本数据，暂不声称双臂一定更省钱或更快。

### 4. 长条目核对语义单元，机制条目核对消费链

长叙事逐项检查主体、动作、对象、关系、范围、时序及确定性；找到一个问题后仍需覆盖余下内容。例如三臂无匹配观察的项目涉及“通常”限定、推测变确定，以及奔忙中停下张望的动作遗漏。该检查不是逐词对译要求，裁决仍须考虑中文等价表达和段落补足。

机制描述另查触发事件、资格条件、数值单位、叠加方式、作用范围和实际参数消费。区分“快照中已核实”与“目标版本适用”：DLC版本未绑定时不通过投票消除pending。共享组件、源码或名称映射的缺口应集中补证，避免各模型重复猜测。

### 5. 下一次只做有界验证，不继续顺序堆组

10条校准完成后，可另取40条未审新样本验证候选流程。按组件、文本长度／类型分层，用固定随机种子抽取，记录抽样框与各层数量；不直接续跑原第15组。校准集与新样本结果分开，不把看过旧裁决的样本当作新测试。

新输入删除历史审核状态、旧finding等元数据，仅保留理解译文所需的原译、上下文、术语适用规则和来源说明。冻结客户端、通道、提示和重试规则；若纳入Gemini，使用单一固定通道。

预先指定评价项：有效问题条目、规范化缺陷覆盖、第二臂新增缺陷、错误理由、共同阴性漏项、完整交付率、核验分钟、费用及耗时。评价长条目时优先看原子缺陷覆盖，不能只看“这条至少找到一个问题”。参考核验尽量由人工先独立判断、再核对匿名观察；换一个模型家族只能降低部分相关偏差，不能产生人工金标准。

完成40条即停止，不因结果接近预期而追加样本。是否有限试用双臂，应根据事先约定的新增有效缺陷与可接受核验负担决定；当前没有证据支持一个通用成本阈值。证据或成本数据不足时，结论保持未决。分层样本不均时分别报告，不用未经校正的混合比例代表全库。

## 建议保留的现有做法

保留冻结输入、同组同提示、原始报告、匿名映射、逐claim证据、原判不追认计分、失败运行单列及完整交付检查。此次主要优化发现与裁决质量，不需要先增加编排层级或重写整个流程。
